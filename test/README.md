# 回归测试

两套独立验证，覆盖 v1.11.0 的两处关键改动。

## `port-probe.test.mjs` — 测速代理端口探测

对应 bug：host 端从 3095 起自增最多 20 个端口（3095–3114），浏览器端却只探 3095–3099。
当 3095–3099 被**非本插件的本地服务**占住时，本实例的真实代理落到 3100+，
浏览器探不到 → `no_proxy` → 测速静默失效。旧判定`r.ok || r.status === 204`
还会把任何回 200 的无关服务误认成代理。

跑法（需Node 22+）：
```bash
node test/port-probe.test.mjs
```
7 个场景：正常命中 / 旧上限内 / 旧代码失手边界 / 中段 /范围上界 /
旧代码误连对照 / 全是占位者时应返回 null。

## `verify-gate.py` — 安装脚本版本闸门

对应逻辑：安装脚本只拦 DSH 0.3+（0.1.5 ~ 0.2.x 一律放行）。
校验 `install.bat` 的 findstr 与 `install.sh` 的 grep 判定等价且正确。

跑法：
```bash
python test/verify-gate.py
```
20 个版本号：0.1.x / 0.2.x 全放行，0.3.x / 0.9.x / 1.x / 2.x 全拦截。

## `test-v1120.py` — v1.12.0 新增逻辑（纯函数级）

覆盖三组：semver 比较 / 远程 `plugin` 段落安检过滤 / 测速历史持久化的序列化与恢复规则。
起服务、占端口、读真实文件都不需要，任何环境都能跑。

跑法：
```bash
python test/test-v1120.py
```
54 项断言。其中一条是**跨文件一致性检查**：
`help.json` 的 `plugin.latestVersion` 必须等于 `lib/client.js` 的 `PLUGIN_VERSION`。
这两个数只要有一个漏改，版本提示就永远不触发 —— 这条断言就是那道漏改的兜底防线。

## 跑测试前的环境要求（两条都要看）

⚠️ **`port-probe.test.mjs` 必须先关掉所有 DSH 实例**。

该测试要真实监听 3095–3114。若你的 DSH 实例正在运行，它的测速代理正占着 3095，
测试会直接崩在第一行：

```
Error: listen EADDRINUSE: address already in use 127.0.0.1:3095
```

⚠️ **退出码 0 不代表测试通过**。上面这个崩溃在某些环境下表现为
「零输出 + exit 0」，看起来像成功，实际一行都没跑。请以输出里的
`总计 N 个场景，通过 N` 为准，不要只看退出码。

⚠️ 两者都**不要**用带代理的环境跑端口测试（代理会劫持 127.0.0.1 请求）。
若怀疑被代理影响，用 `env -u http_proxy -u https_proxy` 前缀跑。
